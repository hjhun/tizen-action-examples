DisplayPresentation

A calm, deterministic viewing surface for a provider-produced A2UI Presentation. It follows One UI’s large, readable content hierarchy without copying proprietary assets.

Goal, users, and non-goals

Users: a person reviewing an agent-selected result and an agent requiring inspectable rendered context. Goal: make a bounded Presentation understandable from a TV distance. Non-goals: web browsing, arbitrary HTML execution, editing source data, network fetching, or persistent document storage.

Navigation and input

Initial focus: content card (when a presentation is visible) D-pad / arrows: retain card focus; move inside expanded fields when present Enter / Space / tap: expand or collapse supported detail Back / Escape: detail or error → prior valid presentation → application back behavior Pointer: activation follows the same card action Modal rule: error/detail owns focus until dismissed; dismissal restores the invoking card

Visual and accessibility policy

Reference canvas: 1920×1080. The physical root covers the window; one top-left design canvas receives the centered uniform inset-aware transform. Content uses 72 px outer safe margins, an 18 px card radius, high contrast near-white text, restrained blue focus/accent, and generous line spacing. Text is bounded and ellipsized before it can overflow. Every interactive card has an accessible label; color is never the sole state signal.

Agent contract

Show(Presentation{Template, Document}) → validate bounded JSON and supported A2UI roots → render immutable snapshot → publish display:presentation:active ViewAnnotation → agent may GetAnnotatedViews / GetFocusedView / FindById → View_ToPresentation returns matching Template + Document JSON

The nested Annotation carries EntityType, EntityId, and generated Presentation EntityInfo; enclosing View carries actual measured bounds and focus.

Acceptance and evidence plan

  • Host: valid, malformed, oversized, unsupported, and mismatched A2UI payloads; viewport and cancellation tests.
  • Target: explicit app provider discovery; Show success and negative typed Status; View lookup/focus/A2UI round trip.
  • Visual: empty, presentation focused, expanded detail, malformed, and unsupported screens via native Aurum screenshots after state-changing input.
  • Profile scope: Common Emulator evidence and TV/product evidence remain separately reported.
