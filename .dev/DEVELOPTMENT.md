# Development

## Inputs Used

- Prompt: implement Calendar ViewAnnotation and connect the annotated Entity via generated `ToJson()`.
- Follow-up: `ToPresentation` must return an A2UI JSON Template.
- Source: Calendar domain, app, Calendar provider, generated internal View binding, and `default-actions` View/Presentation schemas.
- Target: Public Tizen 10.1 Common emulator (`emulator-26101`).

## Implementation Summary

- Added a separate `Calendar.ViewActionProvider` adapter for `Tizen.Internal.Action.View`; the Calendar app starts it at composition-root startup.
- On each NUI render, current selected-day event cards are published as `TizenEntityView` objects with a required `Annotation`.
- Annotation identity is `EntityType=Tizen.Entity.Calendar` and `EntityId=<CalendarEvent.Id>`.
- `Annotation.EntityJson` is generated by constructing the existing generated Calendar DTO and calling its generated `ToJson()` directly. It is not a manually assembled duplicate representation.
- Added `FindById`, `GetAnnotatedViews`, and `GetFocusedView` snapshot discovery. The provider protects its mutable published view list with a lock.
- `ToPresentation` validates the ViewAnnotation, parses its generated Entity snapshot, and returns A2UI JSON:
  - `Template`: an A2UI `surfaceUpdate` containing a `Column` and title/time/location/note text components.
  - `Document`: a matching A2UI `dataModelUpdate` populated from the Calendar Entity.
- Manifest metadata advertises all internal View Actions, including `View_ToPresentation`.

## Code Quality Notes

- Style: nullable-aware C# adapters and Tizen-free domain helper.
- Thread safety: provider view snapshots are published/read under a single lock.
- Generated source: never hand-edited; generated from the full positional View category.
- Known limitation: published view Bounds are synthetic zero values until real NUI geometry can be captured through a stable API seam.
