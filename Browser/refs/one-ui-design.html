Browser — One UI product design contract

TV/large-screen Tizen을 위한 차분한 웹 작업공간. Samsung Internet의 콘텐츠 우선, 넉넉한 여백, 명확한 상태 전달 원칙을 참고하되 독점 화면이나 자산을 복제하지 않는다.

1. 제품 목표와 범위

사용자 목표

URL 또는 검색어로 실제 웹 페이지를 열고, 탭·방문 기록·북마크를 통해 다시 찾으며, 현재 페이지를 Agent와 안전하게 공유한다.

대상

리모컨/D-pad 중심의 거실 사용자, 키보드·포인터·터치를 병행하는 사용자, 그리고 Action/Entity 문맥을 사용하는 Agent.

비목표

정적 가짜 페이지, 계정/동기화, 비밀 모드의 영속화, 쿠키·암호·양식 입력값의 노출, 근거 없는 새 public Action.

실제 Tizen.NUI.BaseComponents.WebView가 탐색의 핵심이다. 엔진·네트워크가 target에서 사용할 수 없으면 화면은 명확한 unavailable/error 상태를 보여 주며 성공을 흉내 내지 않는다.

2. 정보 구조와 화면 목록

3. 핵심 흐름

주소/검색 입력→비동기 load + progress→제목/URL 확정→기록·현재 Entity 갱신

새 탐색은 이전 탐색의 CancellationToken을 취소한다. 늦게 도착한 callback은 tab ID와 navigation version이 현재 값과 일치할 때만 UI를 갱신한다. timeout/offline/error는 Retry와 Back을 제공하며 UI thread를 막지 않는다.

탭 카드 선택→작업공간 복귀→실제 focus/geometry 재발행

4. 입력·포커스·접근성

입력규칙
D-pad / remoteLeft/Right는 chrome 또는 카드의 순서 이동, Up/Down은 chrome·content·dock 영역 이동, Enter는 활성화한다. disabled navigation control은 포커스 가능 여부를 구현 시 일관되게 정하고 상태를 읽는다.
KeyboardTab/화살표는 같은 논리 순서를 따르고, 주소 입력은 Enter로 submit, Escape/Back은 modal 먼저 닫는다.
Pointer / touch첫 pointer 동작은 target을 focus하고 다음 activation을 수행한다. hit area는 시각적 아이콘보다 넓고 label을 제공한다.
Accessible states선택 탭, load progress, disabled Back/Forward, 오류 이유, destructive action을 text와 충분한 대비로 전달한다. focus ring은 #0b6cff 계열 고대비 외곽선이다.

5. 시각 토큰과 responsive 정책

톤

soft background, surface, restrained primary blue, 짙은 ink와 muted secondary text.

계층

상단 chrome은 짧고 안정적이며, page content가 가장 큰 면적을 차지한다. dock은 명확한 상태를 가진 소수의 명령만 둔다. overlay는 배경보다 한 단계 높은 elevation을 갖는다.

1920×1080 reference canvas

물리 root는 full-window background. WindowSize와 GetInsets() 후 하나의 centered uniform, top-left-pivot canvas transform을 적용한다. typography/spacing/radius/focus/overlay를 정확히 한 번만 scale한다. invalid geometry에서는 기존 root를 유지한다.

6. Action · Entity · ViewAnnotation

계약제품 의미와 안전 경계
Tv_Tizen.Action.Browser_Go검증된 Tizen.Entity.Browser URL을 실제 runtime으로 연다. 성공은 navigation 요청 수락이며, 완료 상태는 GetCurrent로 확인한다.
GetCurrent / GetBrowserByIds현재 공개 가능 페이지와 안정 ID resolver. resolver는 요청 순서·중복을 보존하고 unresolved ID를 명시한다.
ToCalendar / ToPresentation충분한 페이지 정보가 있을 때만 handoff/presentation을 만든다. 불충분한 정보는 typed failure이며 추측하지 않는다.
View provider현재 보이는 normal-mode page/tab만 per-surface View ID로 발행한다. enclosing View의 measured bounds/focus와 nested Annotation.EntityType, EntityId, generated EntityInfo를 사용한다. private content, cookies, form data는 제외한다.
View_ToPresentation동일 generated Entity JSON에서 대응되는 surfaceUpdate Template와 dataModelUpdate Document를 별도 JSON으로 생성한다.

7. 검증 및 screenshot 계획

구현 전 mockup은 design reference일 뿐 실행 증거가 아니다. Common Emulator에는 package 설치 후 Aurum으로 다음 state를 native screenshot으로 각각 확인한다: 홈/초기 focus, 실제 reachable page load, load progress, timeout 또는 offline/error + Retry, 탭 관리자 focus, 기록/북마크 empty·result, detail/삭제 Cancel, ViewAnnotation-focused actor. tree가 비어 있으면 D-pad/좌표와 매 단계 screenshot postcondition을 사용한다. target profile·resolution·fixture provenance를 README에 기록한다.

host test, build, TPK payload/signature, installed Action RPC, real web navigation, View/A2UI, Aurum UI evidence는 서로 대체하지 않는 gate이다.
